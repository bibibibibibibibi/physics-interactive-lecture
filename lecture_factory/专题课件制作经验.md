# 专题课件制作规范与交付流程

更新日期：2026-10-08。本文件是 **special 专题系列规范的单一入口**；其他说明只引用本文件，不另建一套完成标准。适用于 sp1–sp8 及后续约20分钟的专题节段，使用 special 主题、分段导航、随堂选择题和嵌入媒体。第九章等常规课堂继续沿用 [README.md](README.md) 的常规流程与 default 主题，不套用专题时长、配比或题后留白策略。

规则来源包括原 PPT 的教学要求、既有制作经验及[真实问题复盘](../docs/special-series-review.md)。sp1 的历史实现不能直接当作已核准教学范本复制；其当前修订版已完成独立内容/物理复核、真实配音、统一技术验收和原用户局部入口验证，证据为 `work/special-series/integration/sp1-final-review.json`（SHA `e66da0c71490864d2c70bcf5cfe371208b290ac9ccdbf312e19774331b34fa71`）。**八课完整人工听审和教师最终教学核准仍全部pending**。下一批先从sp1或sp2选定一课，补齐完整听审、教学核准及约定用户验收，才登记为完整参考节段；绑定原稿、源、音轨、播放器及核准范围，不只写课名。本次仅整理规则，不启动下一批或批量重做课程。

## 一、教学、视觉和媒体要求

1. 推导不跳步：交代从哪条已学规律出发、模型条件、推导和可检验结论；矢量、定轴分量与特殊情形分清，不能用类比代替证明。跨领域应用重新说明物理对象、测量量和适用边界。
2. 引入与小结呼应；课中术语、指向位置和实际素材一致。封面不抢答引入问题，后文不凭空出现未演示的器具或现象。避免无教学目的的公式重复；必要的推导引用、比较或迁移可重列，并说明用途。
3. 随堂自动暂停题用选择题，有真实作答入口、正确项、错误项与解析。题前先完整口播问题、必要前提和作答邀请，题干与口播含义一致；题前及等待作答时，音轨、屏显、热点、默认QA和可滚动的字幕整列表均不得提前露出答案或解析，作答后按教学步骤揭示。验收须实际查看各入口及未来字幕句，不能只查音轨锚点或当前高亮句。避免刚给答案就原样提问。开放探究保留学生先独立判断、理由、证据与修订的任务，不能仅用选择题替代整项学习活动。
4. 时长按真实教学节奏安排。专题通常约20分钟，具体目标区间先记录；新授与应用约2:1，须说明每段归类、实际音轨时长、必要演示/观察及用户自主暂停时间。讲稿字数或某次TTS语速只能帮助起草，不能证明时长达标。先测讲授、计算、观察和回答问题所需时间，最终用完整真实PCM及实际媒体校准；不足时补有教学目的的推导、练习或操作，过长时减少冗余。**禁止无意义留白、慢放或循环凑时长**；自主答题/手调时间单列，不冒充固定音轨时长。
5. special 主题从原PPT提取：淡蓝渐变底、logo右上、无通栏页眉字、页内顶格小节标题，封面/目录不加小节标题、封面无页码；目录保留重点/难点标记。`sections` 按目录大段，段首页对应真实内容起点。正文、公式、媒体、页脚和页码均检查最终步及关键中间步；同时实际查看默认教师及激光等姿态、视频控件与提示条，不能遮挡16:9窗口或全屏正文、图轴、署名、页脚和页码。
6. PPT接收先核对真实页序、隐藏页、备注、动画、公式、图片与媒体关系；XML提取后逐页查看可见画面，**图片内文字、公式、实验记录和作业/预习不能由XML空白推断为不存在**。OCR只协助定位，关键文字与原画面人工对照；无法辨认登记缺项，不能猜填。视频按完整语义段及转场核对实际画面、内嵌字幕和讲稿；首尾抽帧、文件名或metadata不能证明中段内容。赛事、机构和人物身份及实拍/模拟属性须用实际片头、片尾、相关画面与必要的第一方记录核对，并让标题、讲稿和热点一致；原PPT文字也可能误标，不能因保留原意就照搬事实错误。制作方登记冻结只代表待审快照，未完成独立素材语义复核不得放行配音。保留原文件路径和字节hash，不修改输入，不因为新流程迁移旧目录。分析输出优先复用已有本课 `work/special-series/<id>/source/` 或现有源分析目录，不新建无用途顶层目录。
7. 模拟优先复用原始HTML/原素材，再本地化依赖（vendor/零CDN）、按页选择 embed 档、需要讲稿遥控时加入步进消息与真实父音轨时钟。界面布局与讲稿方位词一致；3D主体与图表刻度清楚。每个模拟cue先登记约定前态、演示起点、终态和变化方向；真实原生音轨从cue前自然播放跨过边界，再回拖重跨，初态和讲解方向须连续，例如收臂不得先伸臂或先降低转速。读取真实HUD、曲线和形体，用教学模型的物理公式与参数独立计算预期，不能复制被测脚本的输出作断言，也不能只验几个边界之外的固定时刻。时间轴状态由当前时刻重建，回拖、重进、迟载不依赖历史消息累积；数据曲线按横轴分桶/排序，重置恢复基准参数并清空轨迹。
8. 有交互用 `html()`，只有动态画面用 `video()`。先核对原PPT的真实媒体、时长、比例和署名；新增素材记录出处与采用理由，H.264/yuv420p等实际兼容性须验证。裁剪、静音或循环服务教学目的，不把片段或给定数据称为实测记录。视频/模拟在课堂真实时间轴上检查暂停、倍率、seek及循环，在静态入口用真实原生控件检查播放、暂停、暂停时拖动/播放中拖动后位置保持及实际帧。浏览器原生控件可能吞掉页面pointerdown；静态控制权不能只靠页面指针事件判定。同step的canplay/重复状态快照不得抢回用户位置，显式step/mode变更才重新对齐；课堂仍由音轨控制。
9. 保留原稿的推导前提、模型边界、实验观察与解释、计算、探究、操作记录、提交与预习要求，并写原页→新页/新活动映射。作业逐项保留必做/选做、轮数、字数、提交物、平台和预习范围，原稿未要求的数字不从另一课套入；合理改编要说明原因与对应证据。物理正确和原教学要求保留是两项独立核查，不能以其中一项通过代替另一项。原AI后台图片、示例会话、六名学生状态不是本项目的真实记录：**零伪造外部后台、学生提交、AI会话或自动生成小结**。可保留原平台地址和教师组织安排；本地预设QA通过不代表外部AI/登录/提交已验收。没有要求真实系统接入时，不自行扩大建设范围；如用户明确要求接入，另登记输入、权限和实际验收。

授权等待期间继续可独立进行的原稿、物理、静态、模型和本地缓存核查，不合成假配音、不伪造完整时轴；同轮未覆盖事项由统筹集中列出**具体文字/数量/hash、接收服务和阻塞原因**。已有有效授权在原范围内继续使用，不重复询问。

同步验收还须检查最后一页的真实结尾：末页 `t_end`、最后页间留白及原生音频 `ended` 后，作业/结束正文仍可查看，回退和重播正常。时钟到终点或 `ended=true` 本身不能证明末页可用。子任务上报的共享缺陷必须进入中央缺项清单，给下一处理人及复验结果，不能仅在交接正文留一个未追踪补丁。

## 三、状态和证据字段

五类状态必须同时记录。`passed` 必须附证据路径、实际检查范围、日期和hash；缺失用 `pending`/`missing`，不靠聊天结束推断。状态值只描述对应维度。

| 字段 | 建议值 | 含义与边界 |
| --- | --- | --- |
| `file` | missing / present / verified | 文件清单与实际字节是否存在、可读并绑定；存在不表示内容、音频或UI通过 |
| `candidate` | draft / frozen / local_passed / failed | 本课私有候选的冻结与本地内容/技术范围，不表示统一版通过 |
| `unified` | not_integrated / staged / technical_passed / withdrawn | 统一服务实际绑定及技术验收；菜单接入不等于完整成课 |
| `user` | pending / passed / failed | 用户实际环境的可见版本/操作检查；headless或另一端口只能作独立技术证据 |
| `human` | pending / passed / failed | 在同字段下分列 `full_listening` 与 `teacher_approval` 的状态、身份、日期、音轨/源版本和范围；两项都通过才passed，不另建竞争台账 |

另列 `authorization`、`required_gaps`、`known_limitations`、`overall_complete` 与 `implementation_status`。`overall_complete=true` 只能在该课全部必需阶段通过、无未解决关键问题、user/human通过时设置。真实配音或菜单按钮有声不证明人听过；技术候选可按用户已授权范围开放且明确标注待确认，不能据此写整体完成。首次制作缺真音轨时只给真实静态入口；已有课堂的修订候选不足不改变旧正式入口。旧有声直链与菜单读取同一正式版本/开放边界，不能因新的候选登记切断旧版。

`implementation_status` 使用 `documented`（规范/说明已落地）、`code_verified`（具体代码已检查并有对应验证）、`code_fixed`（实际代码已修正并验证）、`proposed`（待实施建议）。`code_fixed` 必须给实际diff、版本及测试证据；改文档不能给代码赋此状态。不得写“零问题保证”。

## 四、冻结、授权、缓存与时轴的执行规则

1. 读取同一字节快照生成speech payload/hash，记录冻结源、声音、服务与合成参数。授权记录应能追溯直接人类消息或有效既有授权，明确实际文字范围、接收服务与限定参数。先逐句算“当前需要生成的载荷－可追溯精确成功缓存”，再对需要外发的载荷判已有授权覆盖；真正未覆盖的差集由中央一次汇总句数/字数/文字文件/SHA、服务、声线/参数和原因。已有效许可在原范围沿用，不因新聊天或本地布局/组装重问。全稿登记用于当前源与本地组装版本绑定，不能替代具体授权或扩大外发允许表；许可本身可为整课或增量，以其实际范围为准。历史拒绝、实际网络来源和当前已完成状态分别保留；当前登记不得继续显示已解决的“待授权”，也不得改写旧网络记录。
2. 每次网络尝试及重试前，实际发送入口执行允许范围检查；发送的是核对过的精确文本与参数，而非任意CLI输入。已成功缓存不重发；范围外缓存缺失/损坏即停止，不进入通用整课补配分支。重试同服务/同文本/同配方并记录上限、累计尝试与结果；超时未解决的旧请求不得并行重发。具体重试上限先登记，不因重启或新目录重置。
3. 逐句缓存身份为精确文本＋声音＋合成参数签名；同时核对实际MP3字节SHA、来源sidecar、真实解码帧数及字幕文本。recipe hash不是MP3 hash，页id不是缓存身份。逐页times文本序列必须逐字等于当前 `split_sentences(narration)`。合课音轨验证实际PCM组成、页间间隔、最终编码来源及解码；不能只看时长相同。
4. 重建前保留旧候选与绑定；在本课暂存目录重建、核验、生成manifest，再由统筹晋级。不得删旧音轨迫使合成，不默认清空句缓存或构建目录。需要删除时使用操作系统回收站并记录原路径/回收位置，环境不支持则保留并报告；只有用户明确要求永久删除才走相应处理。
5. **1.2秒题后留白是本项目当前专题策略，不是通用教学定律。** 对声明该策略的候选，完整问题/必要前提/邀请读完后，实际PCM到下一口播不少于1.2秒；若有小幅触发偏移，到下一句至少保留1.15秒。同步重算字幕、step、quiz及媒体锚点，构建前拒绝不满足策略的页缓存。自然测1×与最高2.5×的正确/错误分支，越过quiz.t、下一句未开始、锁播与继续；在自然暂停的等待态实际滚动字幕整列表、打开已显示的热点与默认QA，核对屏显及所有字幕均未抢露解析。程序化设置audio.currentTime只可注明为定点准备，必须随后自然播放越过题点；不得改React state伪造通过。普通旧课不被强制改时轴。
6. 前置检查与实际晋级必须分步执行，先读取并确认检查结果；任何检查失败都停止后续依赖动作。工具需声明字段类型：网络请求数等使用非负整数，开放/完成状态使用布尔值，不能把整数0与false的身份判断混用。依赖命令不得仅用换行连接而任由前一步失败后继续；脚本检查返回码并按工具语义解释实际失败行、stdout/stderr及目标状态。例如已关闭临时端口的lsof无监听是预期结果，合并查端口返回1不能直接推断正式服务异常；正式/临时端口分项核对。跨功能测试须记录当前模式及上一动作结果，并按预期通过真实UI结束上一模式，再核对下一控件的实际事件落点。静态批注canvas开启时会按设计拦截视频区域点击；须区分批注层收到的可信指针事件与视频收到的真实play等事件，不能把未退出批注造成的原生Play失败报成视频损坏。修正测试前提后按原要求定向补测，保留旧失败范围，不追认原套件整体通过。
7. 字节/快照在读取前后核对稳定；制作并发写入的临时文件不能签为稳定候选。每个报告绑定原输入、源、payload、音频、times/weblec、素材及实际请求的入口/JS/CSS/chunks；屏显/模板/间隔hash也单列。前后hash不同先判版本混合，保留原证据，不挑选其中通过项冒称单版全通过。
8. 普通课堂验收入口禁止携带任何`qa`查询键；当前`Home`用`searchParams.has('qa')`判定，`qa=0`也会启用自动巡页并关闭自然题卡触发。QA自动巡检只作诊断，须等待其真实完成，不与手动seek或播放检查并跑，不作为自然题卡通过证据。课堂每页截图/几何测量同时记录并核对原生audio实际时间所属页区间与DOM屏显的唯一页号，预期循环标签、元素数或小节名前缀不能冒充实际页身份；不符即该条失败。静态布局与课堂布局分别登记，只运行静态入口的全页状态不能称课堂全页几何通过；普通课堂固定点页检查也不代表整课自然播放。

### 失败证据与采样合同

失败先冻结当时输入、脚本/工具版本、普通URL、步骤、页号/原生时间/模式、实际事件、失败行和输出，再分为产品、环境、测试或待核实。错误字段先对真实schema；教学断言先对原PPT及独立物理真值；工具成功码、HTTP200、RMS或截图存在不能替代教学/可用结论。截图须等真实淡入完成且页身份一致；字幕滚动、seeking、iframe迟载和父/子时钟须约定稳定条件、时限和原子/配对采样，超时仍失败。时限来源于具体合同和实测，不随失败任意放宽；sp1慢模型0.4秒墙钟范围不能当作所有模型或帧精确标准。公开失败不因后续局部修正消失，新报告明确“旧有效case＋新定向case”的范围。

## 五、并行与中央集成

### 参考节段、容量与在制上限

先做**一课完整参考**：从sp1或sp2选择一课，核准原教学映射、音轨/技术、约定用户环境、完整人工听审和教师最终核准后冻结；目前二者只能作技术参考。其他已授权的独立本地核查可继续，但不能跳过参考闸门启动整批。当前八课人工待审是存量债务，需指定承接人并计入后续可用容量，不因技术通过而从负载中隐去。

“两课制作＋独立复核＋中央集成”是**职责配置，初始新批次总在制课程最多2课**，不是四个位置各再开两课。在制从第2阶段实际开始提取/分析入列，包含制作中、待授权/待复核/待集成/待用户及人工确认，直到交付关闭；第1阶段仅预登记、尚未启动分析的接收材料不计在制，不能先给八课全面提取再称只有两课在制。每课只有一名主写者，独立复核必须不同于该课主写者；中央只承担明确预约的串行发布窗口。

开批前在现有queue填写一个约定工作窗口：主写者可完成数M，独立复核可用时间R/每课内容冻结＋完整候选复核＋返工预留r，中央可用时间I/每课集成＋用户验收＋返工预留i，人工听审/教师可承接课程数H。r/i须为正，用完整参考实际投入估算；难课先校准并调高，不用模型推理强度估算。新批次上限 `B=min(2, M, floor(R/r), floor(I/i), H)`；同一人兼任角色不得把同一时段重复计入。容量不明先1课；任一必要角色无承接窗口，先处理存量债务不新开。此公式是排程规则，尚无自动调度工具，不声称算出B便保证质量。

仅在参考完整、共享版本稳定、接手已确认且复核/中央/人工能覆盖B时使用两课。独审或中央待接候选超过1课、已有预约逾期未接、交接缺字段、共享阻断未关闭或预计返工使容量超限，**立即停止新开并降为1课推进**；不丢弃已在制课程，先关闭最接近交付的完整候选。降单课只减少在制负载，不豁免内容冻结、授权、隔离发布或人工核准门槛；发布保护未准入时只继续隔离分析/候选制作。扩大批次须前批缺项关闭、实际吞吐证明可承接，再单独评估；不能按聊天数、ultra或脚本通过率扩批。

接管者在执行前回复下一动作、输入版本、约定窗口和是否已实际开跑。准备脚本、active状态和任务发出都不算执行完成；统筹核对进程/产物。交接无接管确认不离开本课制作人的责任链；下一个约定复核/集成窗口前仍未接手，由统筹重新指定执行者或降批，不能放任双方等待。

以下问题一发现即升级中央并在现有queue登记：关键物理/原任务/媒体身份不确定；共享协议/播放器或其他课受影响；候选与服务版本不符；已发布课堂不可用；所需外发不在有效许可内；前检失败却有后续写入；实际用户故障。授权问题同时列可继续本地工作和一次具体差集，已有授权不重复问。普通单课局部修项由本课处理，但预计无法在已约定接手窗口完成也须在窗口到期前升级。中央为每个缺项指定ID、唯一处理人、下一动作、关闭证据和复验人；制作人跟踪、独审核验、中央关闭，子聊天结束不关闭缺项。

只有实际依赖变化才要求重建；未变PCM或其他文件保留原字节证据，不能因整份JSON/chunk的hash变化无差别重配音或重跑。

静态HTTP单文件内嵌自己的JS/CSS；更新统一播放器不会自动更新既有导出。共享renderer变化须单列 live 入口与嵌入导出两种依赖，证明内联课程数据、路由和标记保持，必要时重新生成受影响导出并在两入口复验。

共享变更先保存旧源码/绑定，出实际diff与影响清单，再决定回归范围。只改外层路由、侧栏显隐或一个视频时钟时，不泛重跑所有题目；剔除已声明变化后确有源码等价、输入/音轨/题卡不变且旧证据范围适用，才能复用。受影响范围在新会话实际测；共享renderer/协议广泛改变或无法证明影响边界时，扩大到所有受影响课及常规课。单纯chunk改名不是全矩阵失效理由，单纯“逻辑未改”也不是复用证明。

回归清单按实际课程目录、入口与系列合同登记归属，`theme` 只说明视觉主题，不能据此认定课程属于专题系列。`pre_vector` 属普通课堂，即使使用special外观仍保留普通课约定的完整字幕列表等行为；专题题前遮蔽、时长与留白策略只对已确认的专题合同生效。共享修改须覆盖受影响的专题和普通课程路径，不能按theme筛选而漏掉普通入口或把专题策略强加给普通课。

### 串行发布、旧版维持与回滚

晋级一次只处理一课或一组确定共享补丁：候选独审通过→核对稳定hash及前检→保存旧正式版本/入口绑定→构建不覆盖旧版的隔离集成候选→核对候选served bytes/bundle/完整导出与中央风险回归→在约定实际用户环境检查候选→中央短串行切换正式绑定/菜单→原真实入口发布后核对与必要操作→成功登记、失败回滚旧版。候选URL通过不能填正式user通过；第九/十阶段的同环境预验与切换后的实际入口核对分别记录。其他课程加入菜单使全菜单hash变化，不自动判本课内容失败；同时检查本课entry和清单路由边界。单课制作和共享维护可在隔离目录并行；内容冻结签署/许可差集审查按候选版本串行，公共组件发布、正式构建/目录写入和验收窗口串行。冻结后不同课程在已核准范围内可隔离配音，不允许并发改被审输入。
