### 判据设计（几条关键取舍）

1. **压字要看真实渲染，不看估宽**。估宽按 CJK 1.0em 偏保守，会把正常段落报成错误
   （5-1 P9 等 36 条全是假阳性）。DOM 端用「墨迹高度 vs 容器高度」，阈值 1.12 倍 + 6px。
2. **KaTeX 公式块天然比盒子高**，含 `.katex` 的元素不做溢出判定。
3. **图内文字重叠要排除上下标**：两 text 字号比 < 0.72 就跳过，否则每个 `m₁` 都报重叠。
4. **viewBox 只判文字**：线条/色块铺到边界外是设计意图（磁场 × 阵列），文字被裁才是错。
5. **图右界 1800~1910 是既有贴边版式**（老课普遍 1830~1870），不列问题；
   只有 >1910（出画布）和正文左边距 <150 才算错。
6. 封面 P1 不判空白格（留白构图），整幅背景图不判页脚越界。

## 踩坑：批量脚本的 `--apply` 被自己过滤掉

`fix_footer.py` / `shift_margin.py` 开头写
`args = [a for a in sys.argv[1:] if not a.startswith('--')]; apply_ = '--apply' in args`
—— args 里已经没有 `--apply`，所以 `apply_` 永远 False。脚本照常打印「上移 5」，
文件却一个字节没变，重建后复测仍是原值。**修法**：先留 `_raw = sys.argv[1:]`，
`apply_ = '--apply' in _raw`，再过滤。`fix_overflow.py` 因为没过滤 args 才幸免。
教训：凡是「--flag 控制写入」的脚本，跑完必须 `grep` 一次源文件确认真的改了。

## special 系列页脚清零（8 节 → 只剩 sp1）

这些课的页面由辅助函数生成（`line(step,y,t,w=…,x=…)` / `T(step,x,y,w,…)` / `tx(s,x,y,w,h,…)`），
没有逐页块，`fix_footer.py` 完全找不到锚点。先后试了三种定位方式：

1. **`fix_footer2.py`（按页块 + 四元组）** —— 全部「未匹配」，因为课里根本没有逐页块。
2. **`patch_calls.py`（AST 遍历调用）** —— 思路对，但：
   - 一开始要求「所有参数都是字面量」，`tx(0,110,976,1500,45,'…' if activity else FOCUS[…] ,25,MUTED)`
     里有个条件表达式，整条调用被跳过 → 改成逐参数尝试、跳过非字面量。
   - `point_of` 用 `len(line)+1` 累加算偏移，**CRLF 文件差一个字符** → 改用行首偏移表。
   - 辅助函数把 x 藏在默认参数里（`line` 的 `x=125`），x 匹配不上 → 放宽成「w 匹配即可」，
     但一放宽就撞到别的同 w 调用，把 12 处改成同一个 y。**此路放弃**。
3. **`patch_exact.py`（函数名 + step + y + w）** —— 用 step 参与定位后稳定了。
   注意它的去重 key 一开始是 `(step,y,w,h)`，会把「多页同指纹但各自独立写法」漏掉
   （sp6 有 4 个 `line(4,965,…,1660)` 分属不同页），改成不预去重、靠「改完就不再有这个 y」
   天然去重。

最终：sp2(3) sp3(2) sp4(1) sp5(2) sp6(13) analytical-mechanics(1) 共 22 处清零；

## build:slides 阻塞已解决（根因：esbuild.exe 的完整性级别是 Low）

`npm run build:slides` 长期报 `Cannot read file "package.json": winapi error #5`
（Access Denied）。逐层排除：沙箱（绕过无效）、vite 配置格式（.ts/.mjs 同样错）、
缓存（删 node_modules/.vite 无效）、残留进程（杀掉无效）。
最小复现发现**连源文件都读不了**（`Cannot read file "src/slides-main.tsx"`），
但 stdin 模式正常 —— 说明 esbuild 子进程读文件被拒。

用权限查询工具看 esbuild.exe 的 ACL，末尾一行是：

    Mandatory Label\Low Mandatory Level:(I)(NW)

**文件的完整性标签是 Low**，所以 esbuild 进程（Low IL）读不了 Medium IL 的普通文件。

修复命令（改完整性级别为 Medium）：

    <权限工具> "...\node_modules\@esbuild\win32-x64\esbuild.exe" /setintegritylevel Medium

改完立刻能构建（12~20 s）。**以后再遇到 `winapi error #5` 先查文件的 Mandatory Label。**

副作用提醒：杀 `esbuild` 进程会让 **dev server 的编译服务一起死**（页面报
「The service is no longer running」、`/src/xxx.tsx` 返回 500）。必须重启 `npm run dev`。
启动 dev server 时**不要接 `| head`**——head 读满即关管道，SIGPIPE 会把 dev 进程带走。
