### 实际被修掉的矢量错误（都是真错，不是审美）

1. **`work_const`：位移 s 与分力 F cosα 画在同一条线上完全重合**，`s` 的记号还被截在框外。
   → 分层：`s` 单独一层画在路径下方（`Line2Arrows`），力与两个分量都从**同一受力点**
   出发、虚线补齐矩形，`α` 角弧改采样折线。
2. **`work_curve`：F 被画成了沿轨迹切向 —— θ 恒等于 0**，与公式 `dW = F cosθ ds` 直接矛盾。
   → F 与「局部单位切向」严格夹 55°，并画出 θ 角弧。这是最隐蔽的一类错：
   单独看箭头「很整齐」，但整幅图的物理是错的。
3. **`ke_theorem`：曲线上的点与切向是手估的** —— 速度箭尾不在曲线上、方向还指反了
   （切向本该向上偏右，画成了向下）。→ 全部改由贝塞尔解析式给：`P = B(s)`、`v ∥ B′(s)`；
   力由「单位力与单位切向/法向的内积」分解，**保证 `F_t + F_n = F` 严格成立**
   （自检 `|ct|² + |sn|² = 1`）。
4. **`pendulum_arc`：速度方向取了垂直方向的另一侧**（指成左上，应为右下）。→ 修正符号。
5. **`rocket_split`：三个速度矢量原本用了两个不同比例尺** → 统一为
   `100 px ↔ 1.0×10³ m·s⁻¹`，三个箭头长度可直接互相比较。
6. **`mom_cons_pair` 补上第三行 `Σp′`**：第 1、3 行等长且末端对齐，「总动量不变」才读得出来。
7. **`mom_cons_axis` 改成等质量两块**，让三支水平速度与质心自洽（+400 与 −100 的平均恰为 +150），
   质心仍沿原抛物线（灰色虚线）。

### 立成硬规矩（写进本批组件头的注释）

① 矢量箭头**必须从作用点出发**（力的箭尾在受力物上、速度的箭尾在质点上）；
② 曲线上的位置与切向**一律由贝塞尔解析式给出**，不手估；
③ 力的分量由「单位力 · 单位切向/法向」算出，保证合成严格成立；
④ 同一物理量在同一幅图中只出现一次，多次出现必须等长；
⑤ 同一幅图里比较同一类矢量（如三个速度）时，**必须共用同一比例尺**。

## ★ 打通 .ppt 读取：PowerPoint COM 通道修复（本轮最大收获）

**问题**：全库 16 章共 190 个源文件条目，其中 **121 个只有老式 `.ppt`（二进制）**，
`python-pptx` **完全打不开**（`PackageNotFoundError`）。原先 `.ppt → .pptx` 靠 COM 的
`SaveAs(…, 24)`，而 COM 已死 —— 不解决的话第四章往后基本没法做。

**根因（三层叠在一起）**：
1. 本机**只装了 WPS**，`C:\Program Files\Microsoft Office\root\Office16\POWERPNT.EXE` 不存在；
   `PowerPoint.Application` 这个 ProgID 实际由 WPS 的 `wpp.exe` 提供。
2. 注册项 `…\CLSID\{91493441-5A91-11CF-8700-00AA0060263B}\LocalServer32`（32 位视图）
   指向 `WPS Office\12.1.0.20305\office6\wpp.exe` —— **该版本目录已不存在**
   （现装的是 12.1.0.28488 / 12.1.0.29158）。
3. 有一个 **18:00 起的僵死 `wpp.exe` 进程**，一直「拒绝接收呼叫」
   （`RPC_E_CALL_REJECTED`）；且从命令行外壳调 COM 对象的那条路被本机安全策略直接拦。

**解法（`work/ppt_export.py`，已验证）**：
```
taskkill /F /IM wpp.exe                      # 先清僵死进程
python -m pip install pywin32                # 只需要一次
python work/ppt_export.py <源文件> <PNG目录> [另存为.pptx]
```
关键三点：
- **从 Python（pywin32）调，不要走命令行外壳的 COM 对象**（会被策略拦）；
- **必须用 `win32com.client.gencache.EnsureDispatch`（早绑定）**：晚绑定
  `Dispatch()` 虽然能拿到 `Presentations.Count`，但拿到的 Presentation 是
  `<unknown>` 代理，取 `.Slides` 直接 `AttributeError: Open.Slides`；
- 脚本里对 `RPC_E_CALL_REJECTED` 做了重试，并在打开前清掉遗留的 Presentations。

**效果**：`.ppt` 能另存为 `.pptx`，每页能导出 **1440×1080 PNG**，
**公式（Equation 对象）、矢量图、配色全是原样渲染** —— 保真度远高于我为了绕开 COM
写的 `render_slides.py`（那个只能拿到 OLE 的低分辨率 WMF 预览）。
`3-5` 已用新通道导出（10 页，`待处理/ppt35势能源文件与分析/slides_png/`）。

**对已完成三节的影响**：3-1 / 3-2 / 3-4 用的是低分辨率替代方案（公式按教材标准核对过），
内容无误、版式自洽；如果有需要可以用新通道重新对一遍参考图。

**仍要注意**：源 PPT 多为 **4:3**（1440×1080），导出保持原始比例；
`Export(dir,'PNG')` 不给尺寸即为原尺寸。


## 新建 3-5 保守力与非保守力 势能（kin3-5，12 页）

**起点**：`第03章/3-5 保守力与非保守力 势能-副本20250320141212.pptx`（10 页）。
**第一次用修好的 COM 通道取参考图**：`python work/ppt_export.py <源文件> <输出目录>` →

`待处理/ppt35势能源文件与分析/slides_png/`。保真度比前面三节的替代方案高一个档次。

**内容结构**：封面（思考题：沿不同路线搬运，重力做功一样吗）/ 一 万有引力做功
（`F̄ = −Gm′m/r² ē_r`，`dW = F̄·dr̄`）/ 一 引力做功的积分
（`ē_r·dr̄ = dr` → `W = Gm′m(1/r_B − 1/r_A)`）/ 一 弹性力做功（`F̄ = −kx ī`，`dW = −kx dx`）/
一 弹性力做功的积分（F–x 面积，`W = −(½kx₂² − ½kx₁²)`）/ 二 保守力与非保守力
（与路径无关）/ 二 保守力的判据（`∮F̄·dr̄ = 0`，非保守力=摩擦力）/
三 势能（重力/弹性/引力三种 + 零点）/ 三 保守力的功与势能的关系
（`W = −ΔE_p`，四条讨论）/ 四 势能曲线（三条曲线一览）/ 随堂练习（多选 A、C）/
本节小结。总时长 425.7 s（约 7 分钟）。

**新增 5 个图示**（全部静态，遵本批新立的「矢量画法硬规矩」）：
- `grav_work`：万有引力做功。`ē_r`（灰虚线）、`F̄`（红，箭尾在质点 m 上、指向 m′）、

  路径由贝塞尔解析式给出，质点位置与切向都取自 `bezPt` / `bezD1`。
