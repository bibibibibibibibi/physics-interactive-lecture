## 重写历史剥离死 blob（方案 A）：.git 从「将达 1.2 GB」压到 794 MB

### 前置
- 完整镜像备份：`待处理/__归档_2026-10-25/repo-backup-20261025.git`（697 MB，含 10 个 copilot checkpoint ref 与全部分支）
- 装工具：`pip install git-filter-repo`（2.47.0），在 Windows 上要用 `python -m git_filter_repo`，
  `git filter-repo` 不在 PATH。

### 关键认知：删文件不减仓库，只有「对象不在任何历史里」才减
- git 内容寻址：同一份内容只存一个 blob。所以 85.6 MB 的精确重复（sp 课 `assets` 与 `weblec` 副本、
  `poses` 与 `characters`）删掉只减工作树，**仓库体积一分不减**。
- 已入库的文件删掉也不减——对象永远留在历史里，除非重写。
- 真正能减的只有两类：① 本次还没入库且以后也不打算入库；② 重写历史。

### 操作序列（可复用）
```bash
git clone --mirror . 待处理/__归档_<日期>/repo-backup-<日期>.git   # 先备份
git add -A && git commit ...                                      # 先把工作树定稿
# 生成「不在 HEAD 树里」的 blob 清单
git ls-tree -r --format=%(objectname) HEAD → head set
git rev-list --objects --all → cat-file --batch-check → 差集
python -m git_filter_repo --strip-blobs-with-ids <清单> --force
```
结果：2431 个 blob / 640 MB 被替换为空；旧 sp2 素材（media1.mp4 22.8 MB、model3d1.glb 15.7 MB）
的提交记录彻底消失；`kin1-1/audio.mp3` 从 3 个历史版本变成 1 个。main 提交数 50 → 52。

### 坑：filter-repo 之后 .git 反而变大（685 → 955 MB）
三个原因叠加，必须逐个处理：
1. **reflog 让旧提交存活** → `git reflog expire --expire=now --all`（否则 `gc --prune=now` 什么都不删）
2. **repack 保留不可达对象作为 delta 基底** → `repack -a -d -f` 跑 9 分钟只减了 21 MB
3. **旧 worktree 的 index 引用未提交对象** → `.git/worktrees/` 里的 IDE 预热 worktree
   （copilot-prewarm-*）把暂存的 TTS 片段当根，删掉后 `fsck` 报 missing blob

最终有效的做法是**手工重建只含可达对象的 pack**：
```bash
git rev-list --objects --all | git pack-objects --delta-base-offset .git/objects/pack/pack
# 注意：不加 --revs！--revs 要求输入是 revision 名，喂 "oid path" 会报 bad revision
# 生成新 pack（793 MB）后手工删掉旧 pack（953 MB），再 git worktree prune
```
之后 `git fsck` 干净，3679 个对象。
